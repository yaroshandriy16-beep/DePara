# ДеПара

Базовий Telegram Mini App для студентів і викладачів на React, TypeScript та Vite.

## Локальний запуск

Потрібні Node.js та npm. У корені проєкту виконайте:

```bash
npm install
npm run dev
```

Відкрийте адресу, яку виведе Vite, у браузері. Інтерфейс працює і поза Telegram; у такому разі дані профілю Telegram недоступні.

Перевірка типів і production-збірка:

```bash
npm run build
```

Щоб перевірити застосунок саме всередині Telegram, його потрібно розмістити за доступною HTTPS-адресою та відкрити як Mini App через налаштованого бота. Це потребує окремого налаштування; проєкт не змінює бота і не публікує застосунок автоматично.

## Дані та інтеграції

Заняття у `src/data/schedule.ts` демонстраційні й не є розкладом ВНАУ. Інтерфейс `ScheduleSource` залишає місце для майбутнього джерела; адаптер ВНАУ та синхронізацію ще не підключено.

Telegram Web App bridge підключено в `index.html`, а роботу з профілем винесено у `src/lib/telegram.ts`. Ім’я та фото з `initDataUnsafe` використовуються тільки для відображення. Цим неперевіреним даним не можна довіряти для авторизації; для неї потрібна перевірка підписаних даних Telegram на сервері.

## Публікація на GitHub Pages

Проєкт підготовлено для GitHub Pages, зокрема для адреси з назвою репозиторію в шляху. Для публікації потрібен репозиторій на GitHub, де дозволено використання Pages. Після завантаження коду в репозиторій:

1. У **Settings → Pages → Build and deployment** оберіть джерело **GitHub Actions**.
2. У вкладці **Actions** відкрийте **Deploy to GitHub Pages** і запустіть **Run workflow**. Публікація запускається вручну, а не при кожному push.
3. Після успішного виконання відкрийте HTTPS-адресу, показану в результаті workflow або в налаштуваннях Pages. Сайт GitHub Pages може бути загальнодоступним.
4. Використайте це посилання для налаштування Mini App у тестовому боті через BotFather. Основний бот змінювати не потрібно.

Файли workflow самі по собі не створюють репозиторій і не публікують сайт; для цього потрібні зазначені вище дії в GitHub.

## Друга ітерація

Під час першого входу оберіть роль та дані з вигаданого демонстраційного каталогу. Вибір і оформлення зберігаються локально в браузері. Розклад повторюється за днями тижня і не є розкладом ВНАУ; погода також демонстраційна. Чисельник і знаменник ще не налаштовані. Погоднішні «вікна» викладача обчислюються тільки між його демонстраційними заняттями. Зошит, чати й друзі поки не працюють. Погоднішній перегляд поширення нічого не надсилає.

Для перегляду на iPhone в одній мережі запустіть `npm run dev` на комп’ютері та відкрийте в Safari адресу мережі, яку покаже Vite. Це локальний перегляд у браузері, а не Telegram Mini App. Для тестування в Telegram потрібне доступне HTTPS-посилання на цю версію; GitHub Pages залишатиметься попередньою версією до окремої публікації.

## Екран «Сьогодні»

Активний демонстраційний розклад можна змінити через назву групи. Додаткові групи та вибір зберігаються локально і не змінюють основну групу профілю. Дані демонстраційних занять доступні лише для групи МН-21; для інших груп застосунок показує, що дані недоступні. Розклад ВНАУ не підключено.

Погода для Вінниці запитується з Open-Meteo без запиту геолокації. За відсутності відповіді використовується останній збережений результат із позначкою часу або показується недоступність. Погодні ефекти й анімації регулюються в профілі або у деталях погоди; системне налаштування зменшення руху також враховується.

## «Розклад» і поширення

На вкладці «Розклад» доступні календар тижня або місяця та вибір дня. Іконка поряд із заголовком відкриває стан джерела: поточний розклад демонстраційний, синхронізації немає. Даних для обчислення чисельника та знаменника немає. Кнопка поширення формує текст із демонстраційними заняттями на вибраний тиждень чи місяць. Вона використовує системне меню, якщо воно доступне, інакше пропонує копіювання тексту; публічний доступ до чужого розкладу не створюється.
