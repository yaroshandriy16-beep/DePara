# Автоматичне оновлення ВНАУ

Скопіюйте `parser.py`, `requirements.txt` і `.github/workflows/update-schedule.yml` у корінь свого GitHub-репозиторію (workflow у відповідну вкладену папку).

1. GitHub → Settings → Actions → General → Workflow permissions → Read and write permissions.
2. Actions → Update VNAU schedules → Run workflow.
3. Спершу для безпечної перевірки на комп'ютері: `pip install -r requirements.txt` та `python parser.py --group 3641`.
4. Після успішного повного запуску з'явиться `data/catalog.json` і `data/groups/<ID>.json`. Файл `schedule.json` лишається сумісним з попереднім застосунком для групи ЕІ-23-1.

Увага: поточний `app.js` працює лише з одним `schedule.json`. Щоб показувати всі групи, треба окремо оновити frontend: читати `data/catalog.json` та за вибраним ID завантажувати `data/groups/<ID>.json`. Не слід вважати, що сам парсер вже додає всі групи в інтерфейс.

Скрипт зчитує лише структуру BUZ (`structureId=0`). Коледжі не охоплені. Автоматичний запуск запланований 4 рази на добу, а не щогодини, щоб не перевантажувати сервер. Важливо отримати дозвіл/узгодити частоту масового зчитування з адміністрацією ВНАУ. Якщо повний запуск виявиться надто тривалим, потрібно розбити оновлення на партії.

Під час помилок окремі JSON не перезаписуються, а повний каталог оновлюється лише після повного успішного обходу. Якщо сайт віддасть валідну, але порожню таблицю, це поки вважається порожнім розкладом; для production бажано додати додаткові перевірки аномального скорочення кількості занять.
